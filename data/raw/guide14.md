# 数字新手村 · 零基础教学指南

版本：V0.1 · 2026-09-24

文档定位：这是一份假设地图。核心假设是——AI 可以解释用户已经提出的问题，却很难主动补齐用户甚至不知道应该问什么的前置认知，新手村的任务是把隐性的前置步骤、词汇、选择、风险和成功判断显性化。

本文档供新手解答疑问，也供战队培养队员或相似情况使用。

零基础用户卡住，不是不会编程，而是根本不知道这个编程世界有哪些零件、它们为什么存在、彼此怎么连起来。请阅读整个文档后，仍有疑问再去请教。同样在此申明，当你完全不具备阅读文档的耐心，或者不会使用 AI 工具总结，强烈建议转专业或进行其他发展规划，不参与项目与科研工作。

## 认知断层全景

下表是新手首次做 AI 项目时最典型的十九个断层，用途是"对照定位"。以下是常见的新手认知断层，请确保你的队员/学弟学妹理解这些前置知识，再开始项目的制作，不要强行为难你的队员/学弟学妹；当他遇到问题时，在这里找到最接近的一条并进行解答。

### 断层 01–05

断层 01 · 我到底在做什么
真实状态："AI 项目"与 AI 混为一谈，不知项目由目标、输入、处理、输出、界面、数据、模型、部署组成。
脑内问题："做个 AI 项目"像一句话，我却不知从哪开始？

断层 02 · 选什么工具
真实状态：不知模型、AI 网站、API、代码编辑器、GitHub、数据库、部署平台分别是什么。
脑内问题：我为什么不能只打开一个 AI 网站把它做完？

断层 03 · 账号与身份
真实状态：不知"网站账号""开发者账号""API 账号""GitHub 账号"分别是什么。
脑内问题：为什么做一个项目要注册这么多地方？

断层 04 · 钱与 API
真实状态：不知 API 与会员订阅的区别，不知什么付费、什么免费、额度在哪看。
脑内问题：为什么已经开通 AI 会员，代码里还要另外买 API？

断层 05 · 密钥与安全
真实状态：不知 API Key 是什么，也不知为什么不能截图、上传 GitHub 或随手发给别人。
脑内问题：为什么这串字符不能直接复制到代码里？

### 断层 06–10

断层 06 · 软件环境
真实状态：不知一个 AI 项目需要装哪些软件，也无法判断"我的电脑有没有准备好"。
脑内问题：我需要安装什么？装到哪算成功？

断层 07 · 终端与命令
真实状态：看到黑窗口陌生，不理解"当前目录、运行命令、参数、报错"。
脑内问题：我要把这句话粘在哪里？出现一大堆字是不是报错？

断层 08 · 文件与路径
真实状态：不理解文件夹、相对路径、绝对路径、工作目录、扩展名。
脑内问题：我明明把文件放电脑里了，为什么程序说找不到？

断层 09 · 代码与项目结构
真实状态：不知多个文件如何组成项目、前后端如何分工、配置文件是什么。
脑内问题：为什么不能把所有代码写进一个文件？

断层 10 · 数据与输入
真实状态：不知模型吃什么：文本、图片、音频、结构化数据，也不了解编码、格式、大小限制。
脑内问题：我的 PDF、Word、表格为什么不能直接"让 AI 看懂"？

### 断层 11–15

断层 11 · 调用 AI
真实状态："调用模型"仍是黑箱，不理解请求、响应、参数、上下文、Token、超时、错误码。
脑内问题：我发出去以后 AI 到底发生了什么？为什么有时成功有时失败？

断层 12 · 费用与资源意识
真实状态：不知模型调用有成本，也不知上下文、图片、音频、请求次数会影响消耗。
脑内问题：为什么只是测试几次就可能花钱？

断层 13 · 调试与报错
真实状态：把报错理解为"项目坏了"，不会读最后几行错误、不知复制什么给 AI。
脑内问题：程序红了一大片，我到底该看哪一句？

断层 14 · 版本控制
真实状态：Git 与 GitHub 是全新世界，不知仓库、提交、推送、分支、README 的意义。
脑内问题：为什么我的代码要放到 GitHub？上传一次就够了吗？

断层 15 · 协作与交付
真实状态：不知如何给别人"一个能运行的东西"，缺 README、环境说明、演示入口。
脑内问题：老师或队友拿到我的代码后为什么还是跑不起来？

### 断层 16–19

断层 16 · 部署与公网访问
真实状态：本地运行与网页上线是两个概念，不了解服务器、端口、域名、反向代理、HTTPS。
脑内问题：我电脑能打开，为什么别人打不开？

断层 17 · 验证与完成标准
真实状态：不知什么叫"做完"，易以"能跑、页面能打开"为终点。
脑内问题：到底怎样才算这个 AI 项目完成？

断层 18 · 求助能力
真实状态：不知遇到问题该提供什么信息，只会说"它报错了""不能用"。
脑内问题：我该把什么发给 AI、学长或老师，才能让别人帮到我？

断层 19 · 认知地图
真实状态：即使单项都会，第一次项目仍可能因"不知下一步"而停摆。
脑内问题：我已经学会很多单点知识，但下一步是什么？

### 六类断层与教学动作

把十九个断层归并后，得到六类可操作的分类。每一类对应一个明确的教学动作，这是把"困惑"翻译成"教法"的关键一步，你可以自行完成，或者使用 AI 工具完成对应的教学工作。

对象断层：核心问题是"不知道世界里有什么"；典型表现是模型、API、GitHub、终端、环境变量等词没有心理模型；对应教学动作是用生活化类比建立"是什么 + 解决什么问题"。

关系断层：核心问题是"知道名词但不知如何连接"；典型表现是不明白"AI 网站、API、代码、模型、项目"之间的关系；对应教学动作是画一张极简关系图，只标当前步骤真正用到的连接。

时序断层：核心问题是"不知先做什么后做什么"；典型表现是同时看到十几个教程，无法判断第一步；对应教学动作是给出唯一确定的行动顺序，每步配一个明确入口。

反馈断层：核心问题是"不知成功还是失败"；典型表现是不清楚安装成功、API 成功、运行成功的观察证据；对应教学动作是每步都给出"成功的长什么样"的可视现象。

恢复断层：核心问题是"不知道失败后怎么办"；典型表现是看到错误就停住，不会回到最近一个已知正确状态；对应教学动作是为每步预设"回到最近正确状态"的路径。

风险断层：核心问题是"不知哪些操作会造成损失"；典型表现是误删文件、泄露 API Key、产生费用、公开仓库；对应教学动作是在真正动手前做安全提示，明确标注代价。

## 动手手册

### 1. 软件安装地图

① VS Code：写代码、改代码的地方（替代记事本）；去哪下：code.visualstudio.com；验证命令与成功的样子：打开后能新建文件即可。

② Python：运行项目的语言环境；去哪下：python.org（Windows 记得勾选 Add to PATH）；验证命令与成功的样子：运行 `python --version` 显示 Python 3.x.x。

③ Git：保存代码、上传到 GitHub 的工具；去哪下：git-scm.com；验证命令与成功的样子：运行 `git --version` 显示版本号。

④ 一个模型 API 平台：你的程序真正去"问 AI"的通道；去哪下：各平台官方站（如 DeepSeek、硅基流动等）；成功的样子：网页能登录，并拿到一个 API Key。

终端在哪里：Windows 搜索"PowerShell"，Mac 使用自带的"终端 (Terminal)"。所有命令都在这里输入。若出现"不是内部或外部命令"，说明没装好或没加入 PATH，把这句话原样复制给 AI 询问。

### 2. 术语速查表

每个有门槛的词都配一句最生活化的解释。碰到不懂的随时查，不要背。如果有需要添加的术语速查表内容，请联系作者获取修订权限进行添加，或者直接进行评论。

#### AI 与模型类

AI 网站：面向用户、提供 AI 功能的网页产品。

大模型 LLM：一个"很会说话的大脑"，你问它答。

Prompt 提示词：你发给模型的那句话，等于给大脑布置的任务。

Token：模型的"字单位"，约 1 个汉字等于 1~2 个 token；说话越长越贵也越慢。

上下文窗口 Context：模型一次能"记住"的最多内容，超了就不记得上面说了什么。

多模态：不仅能读文字，还能看图、听音、读文件的模型能力。

温度参数 temperature：控制回答"保守规矩"还是"天马行空"的旋钮，写代码常调低。

max_tokens 输出上限：限制一次回答的最长长度，超了会被截断。

接口 API：你的程序和模型之间的"正规预约通道"，按次或按字数收费。

#### 开发与操作类

代码编辑器：用来写代码的软件，写、改、调试、运行代码。

终端 / 命令行 CLI：手动给电脑下指令的黑窗口。

命令 / 参数：输入的命令加上附加选项，例如 `git clone 仓库地址`。

当前目录 / 工作目录：程序默认只看的那个文件夹。

相对路径 / 绝对路径：相对是从当前位置走，绝对是从硬盘根目录走到。

依赖 / 包 / 库：你的项目需要别人写好的现成零件，当正式开始编程课程后，你会理解。

包管理器 pip：自动把依赖装上或卸掉的工具，装 Python 时自带。

虚拟环境 venv：给每个项目一个隔离房间，互不干扰，因为不同项目需要配置的环境不一样。

环境变量：存在系统里的全局配置，常用来藏 API Key。

.env 文件：放密钥等秘密的隐藏文件，绝对不进 GitHub！

.gitignore：告诉 Git 哪些文件别上传的清单。

框架：别人搭好的施工脚手架，不用从零砌墙，当正式开始编程课程后，你会理解。

安装依赖命令：Python 用 `pip install 包名`，前端用 `npm install`。

运行命令：`python 文件名.py`，把代码跑起来。

数据库：专门存储和管理数据的系统。

部署平台：把代码/应用发布到服务器上，让别人能访问。

其他语言也有类似的东西，不仅仅是 Python。

#### 账号、资金与网络类

API Key：你程序的"付款密码加身份证"，绝不能外泄；具体在哪里获取取决于你用哪一个 AI，可以询问你的学长。

额度 / 余额：账户里还能花多少调用费，一般在平台控制台可查，402 报错通常就是额度消耗殆尽。

仓库 Repository：GitHub 上装你项目代码的文件夹，可公开可私有。

提交 commit：给代码状态拍一张快照，可随时回到这一刻。

推送 push：把本地快照同步到 GitHub 云端。

分支 branch：给代码开一条平行线，试新功能不破坏主线。

README：项目说明书，教别人这个项目怎么跑。

SSH：连接服务器、上传代码的加密通道。

域名 / 端口 / HTTPS：网页地址 / 服务门牌号 / 加密版网页传输。

反向代理 Nginx：把用户访问转到真正服务上的前台接待。

部署 deploy：把本地项目放到公网，让任何人能访问。

### 3. 实操常见操作

第 1 步 定目标：敲定你接下来要做什么工作任务；成功的样子：定了目标就定了目标呗。

第 2 步 建项目文件夹：在电脑上建一个空文件夹，全程使用它；成功的样子：路径里最好不含中文和空格。

第 3 步 注册：注册各种 AI 平台，并拿到一个 API Key；成功的样子：能登录，Key 已保存。

第 4 步 藏 Key：新建 `.env`，把 Key 放进去；成功的样子：Key 不在代码里！

第 5 步 建环境装依赖：`python -m venv venv`，再 `pip install openai python-dotenv`，这一坨可以根据需求让 AI 来操作；当然了，前面那一步是不可以的，因为 AI 再怎么强大，也没法凭空变出钱帮你付钱买 API；成功的样子：命令执行无报错。

第 6 步 写最小代码：写 `app.py`，读取 .env、调用模型、打印返回，一切的开始就是这么简单；成功的样子：代码能保存且无语法错误。

第 7 步 运行：执行 `python app.py`；成功的样子：屏幕上出现 AI 的回答。

第 8 步 改一个参数：修改提示词或温度，再跑一次（当然你可能用不到这个功能）；成功的样子：改前改后看得见差异。

第 9 步 传 GitHub：依次执行 git init、git add、git commit，建仓库后 push，其实就是上传你的代码；这一项并不强制，你乐意保存在本地也行，不公开也行；成功的样子：网页上仓库可见且含 README。

第 9 步的按钮级操作：

1. 在 GitHub 网页点 New repository，记下仓库地址。
2. 在本地项目文件夹执行 `git init` 初始化。
3. 执行 `git add .`，把所有文件放进暂存区。
4. 执行 `git commit -m "第一次提交"`，拍下快照。
5. 执行 `git remote add origin 仓库地址`，关联远程仓库。
6. 执行 `git push -u origin main`，上传到 GitHub。

若 push 报"被拒绝"，多半是 Key 或 `.env` 混进了提交，或者仓库地址写错。请先创建 `.gitignore` 忽略 `.env` 与 `venv/`，再重新提交。同样这一套操作完全可以交给 AI 处理。

### 4. 救急手册

看到下面这些情况不要慌。

not recognized / 不是内部或外部命令：命令没安装，或没加入 PATH；马上做什么：把这句复制给 AI，检查并重装。

一大堆红色错误：程序停下来告诉你问题，不是坏了；马上做什么：翻到最后几行报错，复制给 AI（你要能看懂你就自己看）。

ModuleNotFoundError：少了某个依赖包；马上做什么：执行 `pip install 包名`。

找不到文件 / Could not open file：文件不在程序运行目录，或名字打错；马上做什么：核对路径与文件名、扩展名。

401 / 403 / invalid api key：Key 错了或已失效；马上做什么：检查 .env 里的 Key 是否复制完整。

429 / quota / insufficient balance：额度用完或触发限流；马上做什么：去控制台看余额，稍等或充值。

402：402 状态码被创建的最初目的是支付系统使用，表示客户端请求的内容只有付费后才能使用，在 AI 项目中也常见于额度用完了；马上做什么：去控制台看余额，稍等或充值。

timeout：没等到回应，通常是网络或内容太长；马上做什么：检查网络，缩短发送内容再试。

模型回答被截断：超出 max_tokens 上限；马上做什么：调大输出上限，或精简输入。

GitHub push 报 rejected / 403：可能混入了密钥，或权限不足；马上做什么：补 .gitignore，确认 Key 没被上传。

### 5. 安全检查单

每次动手前扫一眼，能挡掉绝大多数"不可逆"的损失。

- API Key 放在 .env 里，不在代码、GitHub 或聊天记录中。

- .gitignore 已忽略 .env 和 venv/。

- 知道去哪里查看余额和额度。

- 知道"误改坏了"能怎么找回（Ctrl+Z、重跑、Git 恢复）。

- 每个"要花真钱的动作"前，心里有数大概花多少。

### 6. 万能求助句式

最该学会的不是技术，而是怎么描述问题。标准句式：我在【第几步】输入【某命令】，报了【那句报错】，我想让它【达到某种效果】。

关键是把"环境 + 操作 + 现象 + 报错 + 预期"这五样都给出，而不是只发一句"它报错了，帮我看看"。单纯的截图或者复制报错，AI 不清楚现实情况，很容易产生头疼治头、脚疼治脚的现象，通过加补丁去修复，很容易形成屎山代码，也是常见的错误操作。

## 最短成功路径

零基础的人在最少概念下，独立完成一次完整的"准备 → 调用 → 修改 → 保存 → 验证"。下面七个阶段就是这条路径。

Stage 0 · 我知道我要做什么：新手村职责是把"AI 项目"讲成具体可观察的结果；成功证据：能复述目标。

Stage 1 · 我的电脑准备好了：新手村职责是完成软件、账号、网络、费用准备；成功证据：环境检查通过。

Stage 2 · 我第一次调用成功：新手村职责是帮助理解 API、Key、请求、响应；成功证据：出现预期响应。

Stage 3 · 我第一次改成功：新手村职责是修改一个变量、提示词或界面并看到变化；成功证据：修改前后可对照。

Stage 4 · 我第一次保存成功：新手村职责是完成本地保存或 GitHub 创建仓库；成功证据：仓库可见且可恢复。

Stage 5 · 我知道它为什么成功：新手村职责是让学员用自己的话解释项目各组件的关系；成功证据：通过极简口头解释。

Stage 6 · 我知道下一步去哪里：新手村职责是顺利交给 AI；成功证据：AI 接管项目任务。

当你成功完成以上操作后，说明你已经是一个优秀的工程师了，拿起你的 AI 急头白脸去跑代码了，反正我们也够呛能古法编程了。
