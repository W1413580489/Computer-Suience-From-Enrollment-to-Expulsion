# 红楼梦人物关系探索器

一个用纯静态网页（HTML + CSS + 原生 JavaScript）实现的《红楼梦》人物关系探索工具，
作为"AI 导师引擎"课程的**学生起始项目模板**，供零基础学生上手学习与二次开发。

页面会读取 `data` 目录下的两个 JSON 文件，用原生 SVG 在页面上画出人物节点与人物之间的关系线，
并支持**人物搜索**、**点击高亮**和**关系类型筛选**。

- 没有后端，没有数据库，没有 npm，也不需要任何 API Key。
- 不使用任何外部框架或图表库（没有 Vue / React / jQuery / D3 / ECharts / Cytoscape 等），
  图形全部用原生 `<svg>` 绘制。

---

## 一、运行方法

本项目通过浏览器直接访问本地文件时无法读取 JSON（浏览器安全限制），
**必须用本地服务器打开，不要直接双击 `index.html`。**

在本项目目录下执行：

```bash
python -m http.server 8000
```

然后在浏览器中访问：

```
http://127.0.0.1:8000
```

> 如果你的电脑用 `python3` 命令，也可以执行 `python3 -m http.server 8000`。

## 二、目录结构与各文件职责

```
course_005_red_chamber/
├── index.html              # 页面结构：标题、搜索框、类型筛选、SVG 容器、信息面板
├── style.css               # 页面样式：布局、节点 / 文字 / 关系线的外观与高亮效果
├── app.js                  # 交互逻辑：加载数据、布局、绘制、搜索、高亮、筛选
├── README.md               # 本文件：项目说明与运行方法
├── DATA_SOURCE.md          # 数据来源与整理方式说明
└── data/
    ├── characters.json     # 「人物是谁」：人物的 id、姓名、所属家族、简介
    └── relations.json      # 「谁和谁有关系」：关系两端人物的 id、关系类型、关系说明
```

两个数据文件的分工：

- `data/characters.json` 保存**人物**信息，用 `id` 作为每个人的唯一编号（如 `c01`）。
- `data/relations.json` 保存**关系**信息，用 `source` 和 `target` 记录关系两端的**人物 id**。
- 两个文件**靠 `id` 关联**：`relations.json` 里的 `source` / `target` 必须能在
  `characters.json` 中找到对应的 `id`，关系图才能正确画出。

关键原则：**`app.js` 只管"怎么显示"，JSON 管"显示什么"。**
只要修改 JSON，图上的内容就会跟着改变，不需要改动 `app.js`。

## 三、数据结构速览

`data/characters.json`（数组，每个元素是一个人物）：

```json
[
  { "id": "c01", "name": "贾宝玉", "family": "贾府", "description": "人物简介" }
]
```

- `id`：人物编号，用 c01、c02… 依次递增；**全文件不可重复**。
- `name`：人物姓名。
- `family`：所属家族，可取 贾府 / 史府 / 王府 / 薛府 / 其他。
- `description`：一句话人物简介。

`data/relations.json`（数组，每个元素是一条关系）：

```json
[
  { "source": "c01", "target": "c02", "type": "love", "label": "木石前盟" }
]
```

- `source` / `target`：关系两端的人物 `id`，必须真实存在于 `characters.json`。
- `type`：关系类型，**只能取以下五个固定值之一**：
  `family`（亲属）、`friend`（朋友）、`love`（情爱）、`conflict`（冲突）、`other`（其他）。
- `label`：一句话关系说明。

> 注意：人物的坐标**不在数据里**。`app.js` 会按人物在
> `characters.json` 中的先后顺序，自动把它们均匀分布在一个圆周上。
> 学生不需要理解布局算法，想调整位置只需调整 JSON 中人物的顺序。

## 五、已实现的功能

1. **人物搜索**：在搜索框输入姓名（如"林黛玉"），会定位并高亮该人物；
   没有匹配时只给出提示，页面不会报错。
2. **点击人物**：高亮该人物**直接相关**的关系线（同时匹配 `source` 与 `target`）和相邻人物，
   并在右侧信息面板显示人物简介与关系说明。
3. **关系类型筛选**：下拉框选项由代码从 `relations.json` 中**真实出现的 type** 自动生成
   （并非写死）；选择某类型后，只显示该类型的关系及其涉及的人物。
4. **点击空白处**：清除上一次的高亮与选中状态。

## 六、后续任务方向（可在此模板上继续开发）

1. **完善人物搜索**：支持模糊匹配、拼音首字母、匹配多个候选人供选择。
2. **增强关系高亮**：高亮时把无关人物淡出，或按关系类型采用不同颜色。
3. **扩展关系类型筛选**：支持多选、显示每种类型的数量、与搜索联动。
4. **新增关系**：在 `relations.json` 中追加一条记录（写好 `source`、`target`、`type`、`label`），
   刷新页面即可看到新关系；新增时请按 [DATA_SOURCE.md](DATA_SOURCE.md) 说明补上来源与判断依据。
5. **优化布局**：尝试让关系密切的人物靠得更近，或把同一家族的人物聚在一起。
