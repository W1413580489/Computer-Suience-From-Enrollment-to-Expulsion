# 数据来源与整理说明（DATA_SOURCE.md）

本文件说明"红楼梦人物关系探索器"课程模板中数据（`data/characters.json` 与
`data/relations.json`）的来源、整理方式与使用许可，供学生了解数据从哪来、能不能用、如何补充。

---

## 一、数据来源名称与整理方式

- **数据来源名称**：《红楼梦》公开文本（原著为清代曹雪芹所著，属公有领域作品）。
- **整理方式**：本课程的数据**由课程作者根据《红楼梦》公开文本自行整理**，
  将其简化为一个"人物 + 关系"的结构化数据集。
  - `characters.json` 中的每个人物，均由课程作者从原著情节中提取姓名、所属家族与一句话简介。
  - `relations.json` 中的每条关系，均由课程作者依据原著情节判断后手工录入，
    并归入 `family` / `friend` / `love` / `conflict` / `other` 五种简化类型之一。

**重要说明**：本课程数据**不是直接复制第三方数据集**，
而是课程作者为了教学演示目的、基于《红楼梦》公开文本**自行整理**的简化版本。
它是教学用的示例数据，**不追求、也不等同于完整的原著人物关系**。

## 四、本课程对数据的简化说明

为便于零基础学生理解和上手，本课程对原著数据做了如下**简化**，请注意：

1. **人物数量有限**：只挑选了部分主要人物，未覆盖原著全部角色。
2. **关系类型被归类**：丰富复杂的人际关系被压缩为五种固定类型
   （`family` 亲属 / `friend` 朋友 / `love` 情爱 / `conflict` 冲突 / `other` 其他），
   会损失不少细节与语义。
3. **一人一条简介**：每个人物只用一句话概括，属于高度浓缩。
4. **坐标不写入数据**：图中人物位置由代码按顺序自动生成，与人物在原著中的地位无关。
5. **判断存在主观性**：关系归类（尤其 friendship 与 love、conflict 与 other 的边界）
   依赖整理者的理解，不同的人可能有不同看法。

## 五、学生新增关系时，应如何补充来源与判断依据

当你在 `relations.json` 中**新增一条关系**时，请同时在你的作业报告 / 说明文档中补充：

1. **来源文本**：说明这条关系依据的原著回目、章节或具体情节
   （例如"据第 X 回……"），能引用原文更好。
2. **判断依据**：用一两句话说明为什么把这两人的关系归入你选择的 `type`
   （例如"二人自幼一处长大、情谊深厚，故归为 friend"）。
3. **关系说明**：为 `label` 写一句简短、准确的中文说明，避免含糊。
4. **一致性自查**：确认 `source` 与 `target` 都是 `characters.json` 中真实存在的 `id`，
   并且没有与已有记录完全重复。
5. **必要时更新本文件**：如果你引入了新的资料来源，请在本文档的对应部分补充说明。

这样可以保证数据的**可追溯性**：别人看到一条关系时，
能顺藤摸瓜找到它出自原著哪里、又是如何被判断的。
