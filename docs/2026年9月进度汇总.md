## 一、AI 导师体系（本月主线）

### 1.1 产品定位调整（9/9）

- 定位从「能力测评引擎」转向 **「业务级项目交付 + 面试自查陪跑」**，保留 Git 提交追踪；
- 明确真实技术壁垒：业务项目库、面试问答语料、就业结果数据闭环、工作流集成深度、反「训练项目」机制；
- 排除非壁垒项：LLM 调用、RAG、AI 导师模式、UI 设计；
- 后续修改计划中**明确剔除**终端命令追踪与代码相似度检测。

### 1.2 AI 导师 v2 方案定稿（9/9）

- 不再强制要求部署，定位为**质检式练手**而非能力验证/防作弊；
- 产出**简历文字片段**（非完整简历）；
- MVP 项目留作未来课程计划，不立即执行；
- 保留并改造现有「指导 + 验收」双模式内部集成；
- 解决模型输出漂移：**LLM 只输出逐条 PASS/FAIL/NEED_REVIEW，分数由后端按权重加权计算、状态由代码判定**，防止模型输出漂移。

### 1.3 学术论文写作练习架构定型（9/21）

- 选定「**LLM 判定与评分解耦的确定性聚合架构**」：evidence-anchored、可复现的学术写作反馈引擎；
- 新增 `essay_rubrics.py`（五维 rubric：结构完整、论证链条、证据引用、语言规范、学术诚信）、`essay_review.py`（证据锚定评审链）、扩展 schema 与 API、前端 `EssayView.vue`（设计方案已归档）。

## 二、核心稳定与数据层

### 2.1 会话历史丢失双根因修复（9/21）

- **根因 1**：课程/项目下拉 `v-model` 提前更新值，导致旧对话被保存到新键 → 改用 `:value` + 显式参数传递；
- **根因 2**：验收截图 base64 超出 localStorage 容量 → 快照排除 base64 提交预览；写入失败时进一步排除 review 字段兜底；
- 部署后实测切换任务/课程 + 截图验收，会话持久化正常。

### 2.2 上下文持久化与 JSON 容错体系（9/23）

按《上下文持久化与 JSON 容错-方案设计》落地（步骤 1–5 已完成并上线）：

- **行为级 max_tokens**：llm_client 显式设置 `max_tokens` 并读取 `finish_reason`，截断时续写而非重试；
- **json_repair 第二防线**：`_extract_json` 增加容错解析，杜绝 char 430 截断导致的二次失败与 500；
- **teach 纯文本兜底**：确保学生始终能拿到回答；
- **SQLite 存储层**：新增 `sessions / evidence / review_results / review_failures` 四表，SQLite 作为会话数据唯一真相源（`/opt/xkz-agent/data/engine.db`）；
- **会话真相源改造**：会话身份基于前端生成 uuid（不支持跨设备接续）；新增 `GET /api/ai/session_history` 供前端刷新恢复历史，前端 `slice(-20)` + restoreChat 服务端优先；
- review 结果严格语义校验，未知 rubric_id 不再静默按 weight=1 处理。

> 注：方案步骤 6（输出契约精简：`message` ≤300 字、`verify_steps` ≤5 条硬约束）为**确认的遗漏项，尚未实施**；步骤 7（阈值触发 LLM 滚动摘要）为 V1 明确不做项。
