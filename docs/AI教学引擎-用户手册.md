## 一、快速开始

### 1. 打开页面

访问 https://jnuxky.xyz/teach，你会看到左右两栏布局：

- **左侧**：配置区（API Key、任务选择、模式切换）
- **右侧**：对话区（与 AI 导师聊天）

### 2. 第一步：填入 API Key

AI 导师需要调用大模型来回答你，你需要自己准备一个 API Key。

- 在左侧 **API Key** 输入框粘贴你的 Key（如 DeepSeek API Key）
- Key 只保存在你本机浏览器，不会上传到服务器
- 输入后状态显示"已保存到本机"即生效

> 没有 Key？去 https://platform.deepseek.com 注册获取，新用户有免费额度。

### 3. 第二步：选择任务

- **教学任务**下拉框选择你要做的项目（如"套壳聊天机器人"）
- 下方会显示该项目的阶段进度条（拆解与准备 → 开发与联调 → 提交验收）
- **任务**下拉框选择当前具体要做到哪一步（如"写后端接口"）

### 4. 第三步：选模式，开始对话

选择辅导模式，在输入框打字发送，AI 就会根据你选的模式来回答。

## 二、四个辅导模式怎么选

这是整个工具最核心的概念——**不同阶段用不同模式**。

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   刚拿到任务 → 用 Tutor（教学）                          │
│       ↓                                                 │
│   开始动手做 → 用 Coach（教练）                          │
│       ↓                                                 │
│   遇到报错卡住 → 用 Debugger（调试）                     │
│       ↓                                                 │
│   做完了要验收 → 用 Reviewer（评审）                     │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### Tutor（教学模式）

**场景**：刚拿到任务，不知道怎么下手。

AI 会把任务拆成可执行的步骤，给你引导方向，不会直接给答案，而是通过提问让你自己思考。

**适合问**："这个任务要做什么？""我该从哪里开始？"

### Coach（教练模式）

**场景**：已经开始做了，但进度慢、不确定对不对、需要人推一把。

AI 会追问你的进度，告诉你当前只需要做哪一步，帮你排除干扰。

**适合问**："我做了 xxx，下一步该干嘛？""你看我这样做对吗？"

### Debugger（调试模式）

**场景**：代码报错卡住了，不知道原因。

AI 不会直接帮你修代码，而是引导你定位问题根因，给出排查步骤，让你自己确认后再修复。

**适合问**："报了这个错 xxx，是什么原因？""我这段代码哪里有问题？"

### Reviewer（评审模式）

**场景**：觉得做完了，让 AI 来验收打分。

AI 会对照验收标准逐条评审，给出评分和判定结果（PASS / FAIL / NEED_REVIEW），并说明哪里没做好。

**适合问**：直接提交代码或仓库链接，让 AI 评审。

## 三、AI 回答里的信息怎么看

每条 AI 回复会附带一些标签，帮助你理解它的回答质量：

| 标签 | 含义 |
|------|------|
| `提示 L1` | 当前提示等级（0-5），数字越低 AI 越不给答案 |
| `提示档 2/5` | 已经升到第几档提示 |
| `参考源 3` | AI 参考了课程资料中的几段内容 |
| `评分 85` |（仅 Reviewer）评审得分 |
| `✓ 通过` |（仅 Reviewer）该条通过验收 |
| `调试 2轮` |（仅 Debugger）已经来回确认了几轮 |

### 建议下一步（黄色卡片）

AI 每次回答后，会在消息下方显示一个**黄色建议卡片**，告诉你下一步应该切换到哪个模式。点击"切换到 xxx"按钮即可自动切换。

## 四、GitHub 仓库链接有什么用

如果你在做编程项目，在左侧输入你的 GitHub 仓库地址，AI 会：

1. 自动拉取你的代码结构，了解你写了什么
2. 读取 GitHub Actions 的 CI 运行状态
3. 评审时结合代码和 CI 结果做判断

**怎么填**：粘贴完整的仓库 URL，如 `https://github.com/你的用户名/仓库名`

**不填会怎样**：Reviewer 评审时只能靠你提交的文字描述，缺少代码证据，可能判 NEED_REVIEW。

## 五、学生状态

- 左侧底部显示你的**进度**：已完成任务数、已尝试任务数
- 当同一个任务尝试多次，AI 会自动提高提示等级（从引导 → 给更多提示）
- 点 **重置学生进度** 可以清空所有记录重新开始
- 点 **清空对话** 可以清除当前对话历史

## 六、常见问题

### Q：为什么 AI 不直接给我答案？

AI 导师的设计原则是**不替学生完成思考**。提示等级越低，AI 越只给方向不给答案。你自己想出来的，才是你的能力。

### Q：为什么 Reviewer 判了 NEED_REVIEW？

说明缺少必要的验收证据。检查一下：
- 是否填写了 GitHub 仓库链接？
- 仓库里是否有 CI 工作流（build/test）？
- 是否在输入框中描述了你的完成情况？

### Q：提示等级怎么升？

同一个任务里，你每多发一次消息，提示等级就升一级（L0 → L1 → L2...）。等级越高，AI 给的帮助越具体。

### Q：刷新页面后对话没了？

对话历史存在浏览器内存中，刷新会丢失。但 API Key 和学生进度会保留。

### Q：Key 安全吗？

API Key 只存在你本机的 localStorage 里，每次请求由前端直接发给大模型服务商，不经我们的服务器中转。

## 七、完整使用流程示例

以"套壳聊天机器人"项目为例：

```
步骤 1️⃣：粘贴 API Key，选好任务
步骤 2️⃣：用 Tutor 模式 → 问"这个任务要做什么？"
步骤 3️⃣：AI 拆解步骤后，点建议卡片 → 切换到 Coach
步骤 4️⃣：开始动手，遇到报错 → 切到 Debugger
步骤 5️⃣：做完后 → 切到 Reviewer 提交评审
步骤 6️⃣：根据评审意见修改，重复步骤 5
```
