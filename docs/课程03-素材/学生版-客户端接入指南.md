# 学生版 · 客户端接入指南

把你自己写的 MCP Server 接进 AI 客户端，是课程 03 的第一个交付点。这份指南列出各客户端怎么配，以及**接不上时按什么顺序排查**。

## 一、先明确两件事

1. **传输方式是 stdio**：客户端会以「子进程」方式启动你的 server，通过标准输入/输出通信。所以配置里要写清「用什么命令启动它」。
2. **配置里的命令必须能直接跑**：`command` + `args` 拼起来，要等价于你在终端里手动跑通的那条命令。**先在终端跑通，再写进配置。**

## 二、通用配置形状

```json
{
  "mcpServers": {
    "work-continuity": {
      "command": "python",
      "args": ["/你的绝对路径/server.py"],
      "env": {
        "WORK_DIR": "/你想让它管理记忆的项目目录"
      }
    }
  }
}
```

Windows 提示：
- 路径用绝对路径；JSON 里反斜杠要写两个（`D://code//server.py`），或改用正斜杠
- `python` 不是全局命令时，写解释器绝对路径（如 `.venv\\Scripts\\python.exe`）

## 三、各客户端放哪里

| 客户端 | 配置文件 / 入口 |
|---|---|
| Claude Code | 项目级 `.mcp.json`；用户级 `~/.claude.json` 里的 `mcpServers` |
| Cursor | 项目级 `.cursor/mcp.json`；或 Settings → Features → MCP → Add new MCP server |
| Trae / TraeWork | 设置 → MCP → 添加 server → 选 stdio，填命令与参数 |
| VS Code（Copilot） | 项目级 `.github/copilot-mcp.json` |
| Windsurf | Settings → MCP |
| Cline / Roo | 面板 → MCP Servers → 添加 → 选 `command` |

> 各客户端更新较快，界面叫法可能不同；找不到就在设置里搜 "MCP"。

## 四、接好之后应该看到什么

1. 客户端的 MCP 列表里出现这个 server，状态是「已连接 / 运行中」
2. 展开能看到工具清单（骨架阶段只有一个 `hello`）
3. 在对话里说「用 work-continuity 的 hello 工具跟我打个招呼」，能看到返回文本

**这三个都看到 = 第一个任务完成。**

## 五、接不上时的排查顺序（按这个来，别乱试）

1. **先在终端手动跑** —— 跑不通就是代码/依赖问题，跟客户端无关
2. **看客户端日志** —— 多数客户端有 MCP 日志面板，真正的错误写在那里
3. **核对命令与路径** —— 是否等价于终端里跑通的那条；是否绝对路径
4. **核对解释器** —— 用了虚拟环境，`command` 就要指向 venv 里的 python，而不是全局 python
5. **核对依赖装在哪** —— A 环境装的包，B 环境的解释器看不到
6. **核对传输方式** —— 默认 stdio，写错成 HTTP 会连不上

## 六、常见现象对照

| 现象 | 多半是 |
|---|---|
| 列表里不出现这个 server | 命令/路径写错，或客户端没重启 |
| 出现但显示 error / failed | server 一启动就报错了 → 去日志看 Python 的 traceback |
| 报 `FastMCP was renamed to MCPServer` | 装的是 `mcp` 2.x，代码还是 v1 写法（改导入，或 `pip install "mcp<2"`） |
| 报 `No module named 'mcp'` | 依赖没装在客户端用的那个解释器里 |
| 工具列表是空的 | server 起来了但没注册工具（检查 `@mcp.tool()` 是否漏写） |
